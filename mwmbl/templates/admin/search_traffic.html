Which of User-Agent and Accept-Language arrived, and nothing inferred from it. A missing Accept-Language is a hint that a client is not a browser, and only a hint. neither has stayed empty: the SvelteKit front end's server-side render calls the API through Node's fetch, which sends User-Agent: node and Accept-Language: *, so it lands in user_agent+language alongside every real browser. What it cost us, roughly: a 4xx bought a URL match and nothing else. A 2xx on *_search bought a ranker run - retrieval for every term, completion and bigram, then the model. A 2xx on *_raw did not: get_raw_results is one retrieve of the whole query as a single term plus the blacklist filter, so those are the cheapest requests in the table by a wide margin, and reading this column as uniform cost will overstate them. A client sending queries it never gets an answer to lives in the 4xx column.

Over the last {{ user_agents.days|length }} day{{ user_agents.days|length|pluralize }}, {{ user_agents.request_total|intcomma }} requests counted and {{ user_agents.tracked_total|intcomma }} attributed to one of {{ user_agents.tracked|intcomma }} tracked user agents ({{ user_agents.tracked_limit|intcomma }} kept per day), leaving a gap of {{ user_agents.gap|intcomma }}.

The gap is the tail the trim dropped. It catches a client that randomises its user agent widely enough to overflow the trim, and nothing narrower: a rotation over a small fixed pool never reaches the limit, so the gap stays at zero while the rotation runs. SearxNG is the worked example - gen_useragent() builds every request's User-Agent from two OS strings and a handful of Firefox versions, which is a pool of a few dozen strings and no gap at all. A gap of zero means nobody overflowed the trim; it does not mean nobody is rotating.
